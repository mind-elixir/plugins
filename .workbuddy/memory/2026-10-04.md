## ★ 用户实际遇到的 bug：me-desktop-landing OPML 转换器导出白底白字（真凶）

前面排查的 export-mindmap 库内问题（水印对比度）是真实的但**不是**用户看到的。
真凶在 `me-desktop-landing/components/tools/opml-converter.tsx`（commit 882c352 新增）：

- 构建实例时：暗色模式用 DARK_THEME（文字浅色），并设 `theme.cssVar['--bgcolor'] = 'transparent'`
  （为了让地图融入页面卡片，屏幕上合理）
- 导出时：`exportImageBlob(mei, 'png', { backgroundColor: '#ffffff' })` **写死白底**

**关键机制**：孙节点级别的文字**没有气泡包着，直接画在画布上**。暗色主题的浅色文字
（#cccccc 等）落在写死的白底上 → 白底浅字，正是用户描述的「文字是暗黑模式但背景白色」。
浅色模式不触发 → 解释了「有时候」。实测对比度：暗色主题浅灰字 vs #ffffff ≈ 3.27（弱），
更深的内容层级会更差；换成 #252526 后 15.31。

**为什么必须显式传（用户连环追问后实测闭环）**：exportImageBlob（0.1.10）不传时自动取
`mei.theme.cssVar['--bgcolor'] ?? 基底默认`——但 `??` 只拦 nullish，组件覆写的 `'transparent'`
是非空字符串，库原样拿到 → host background:transparent + canvas fillRect(transparent 合法,
= rgba(0,0,0,0)) → **PNG 全透明**（实测角落 rgba(0,0,0,0)）→ 白底查看器里=白底浅字=原 bug。
所以"不传"恰恰是 bug 本体；显式传实体色是必须的。

**最终定论（库层修复，调用方零传参）**：用户坚持"取主题背景是库的职责"——对。库的洞已补：
`resolveExportBackground` 增加 `isUsableBg`（transparent / rgba(0,0,0,0) / 空串 视为无效），
无效时逐层回退：DOM computed → theme.cssVar → **基底主题色常量**（dark=#252526 / light=#f6f6f6，
镜像 mind-elixir 内置 THEME/DARK_THEME 的 --bgcolor，与库原有 `type 兜底`同一规则，非新猜测）。
实测：transparent 主题 + **完全不传 backgroundColor** → 暗色导出 #252526、浅色导出 #f6f6f6，全对。

**landing 侧收尾（已完成）**：npm 0.1.11 已发布（用户终端 web-auth 方式，registry 索引延迟约
1 分钟——`npm view` 轮询即可）。landing 已 `pnpm up @mind-elixir/export-mindmap@0.1.11`
（pnpm v12 自动在 pnpm-workspace.yaml 加 `minimumReleaseAgeExclude`，刚发布的包有最小年龄
限制，保留否则下次 install 拒装），opml-converter.tsx 已删除 exportBgRef 与 backgroundColor

export-mindmap 0.1.11，transparent 主题、scale:2、不传 backgroundColor）：dark → rgba(37,37,38,255)、
light → rgba(246,246,246,255)，全对。tsc 通过。landing 改动未提交（4 个文件）；

## 修复导出图片「暗黑文字 + 白底」可读性 bug（@mind-elixir/export-mindmap）

### 根因（实测确认，非静态推断）

**先纠正一个容易误判的点**：原实现 `theme.cssVar['--bgcolor'] ?? (type==='dark' ? '#252526' : '#f6f6f6')`
在 `exportImageBlob` 这条路径上**从来取不到背景** —— `??` 兜底一直有效，探针 8/8 场景背景都正确。
所以「原实现背景取不到」这个说法是错的，别再沿用。

真正的两个缺陷：

1. **水印色错（`exportImageBlob` 自身，唯一确证的库内 bug）**：用 `mei.theme.type === 'dark'` 选水印色。
   但 mind-elixir 套用主题是 `{...(type==='dark'?DARK:LIGHT).cssVar, ...theme.cssVar}` ——
   `type` 只是**基底选择器**，用户 `cssVar` 可覆盖任意项，故 `type` 与实际背景可以相反。
   实测 `type=dark` + `--bgcolor:#ffffff` 时浅色水印落在白底上，对比度 **1.08**（完全隐形）；
   反向 `type=light` + 深底为 **1.14**。改为按实际背景的 WCAG 亮度计算后 → 17.40 / 16.10。
2. **调用方裸传（库外，desktop/cloud 侧）**：`MiniMap.tsx:17`、`mind-elixir-cloud/.../mindmap.tsx:631`
   直接把 `theme.cssVar['--bgcolor']` 传给 `domToBlob`/`domToDataURL`，**没有 `??` 兜底**。
   自定义主题省略该键时为 `undefined`。实测后果按格式而异（用真实 jpeg 验证过）：
   - **png** → 角落 `rgba(0,0,0,0)`，全透明 → 在白底查看器里暗色字看起来「白底白字」
   - **jpeg**（MiniMap 实际用的就是这个）→ `rgb(0,0,0)`，**变纯黑底**（不是白底！）
   传 `#252526` 时正常 `rgb(37,37,37)`。所以这处症状是**黑底**，别描述成白底。

### 修复（最终版，只改 index.ts 一个文件）

- `index.ts` 新增并导出 `resolveExportBackground(mei)`：**只认 DOM computed `--bgcolor`**
  （`changeTheme` 必然把合并后的完整 cssVar 写上 container，所以它就是唯一真相），
  → 退化时读 `theme.cssVar['--bgcolor']` → **都没有则抛错**，不再有硬编码颜色兜底。
- 新增 `contrastColor(bg)`：按 WCAG 相对亮度算水印色，不再看 `theme.type`；解析失败抛错而非默认深色。
- 顺带删掉遗留的 `console.log('marginL', ...)`。

**分层原则（用户纠正后确立，务必遵守）**：mind-elixir 层（`index.ts`，有 `mei`）负责解析背景；
`scst.ts` 是通用 DOM→图片引擎，**不做任何兜底、不读 `--bgcolor`、不猜颜色**。它只认显式传入的
`backgroundColor`；不给就是透明（透明是合法需求，用于叠加素材）。也不要向上遍历祖先找背景——
那是替调用方做决定。解析不到就让调用方**显式传 theme / backgroundColor**，或得到一个可修复的报错。

### 验证方式（headless Chrome + CDP，A/B 反事实）

探针 8 场景（含阳性对照 A/B 基础主题、带 negative 对照的 MiniMap 裸传路径），比对**真实导出位图像素**
与屏幕 computed color 的 WCAG 对比度。修复前 `git show HEAD:` 取原始文件构建，修复后重建，同一探针跑两遍。

结果：`exportImageBlob` 路径 8/8 背景正确（含 G/H 省略 `--bgcolor` 场景）；水印 C 1.08→17.40、
D 1.14→16.10；裸传路径 G/H 回归透明（符合预期，引擎不再兜底）；其余场景逐像素一致，无回归。

### 踩坑记录

- **`git stash` 会吞掉未提交改动**：`git stash` 后紧接着的构建失败，我误判成 stash pop 完成。改用
  `cp` 到 `/tmp/fix-backup` + `git show HEAD:file > orig.ts` 做 A/B，不再依赖 stash。
- **`tsc --noEmit` 在 composite 项目里是空跑**：mind-elixir-desktop 的 `tsconfig.json` 是
  `files: []` + `references`，必须用 `npx tsc -b --noEmit` 才真正检查。我一度被假通过骗到，
  差点交付一个 desktop 编译不过的改动。
- **探针度量缺陷**：①取「最常见文字色」会偏向子节点色而漏掉根节点 → 改为评估所有颜色取最差；
  ②未考虑节点自身气泡底，导致白字在深色气泡里被误报为「不可见」；
  ③水印取「与背景差异最大的单像素」会撞上连线像素（抓到 `rgb(0,8,30)`）→ 改为按颜色量化聚类取像素数最多的簇。
  这三条都是先看到不合理数值才查出来的，不能直接采信第一版指标。
- **CDP 会话通道**：`Target.createTarget` + `attachToTarget` 的 session 会被关（WS 1006）。从 `/json/list`
  挑 `type==='page'` 的 target 直连 `webSocketDebuggerUrl`，命令不带 sessionId 才稳。
- Chrome 无头需 `--no-sandbox --in-process-gpu`，否则 GPU process 自杀。
- 探针改页面代码后必须 `Network.setCacheDisabled`，否则拿到旧页面数据（我因此误报过一次 KeyError）。
- `git stash` 前后务必 `md5 -q` 校验文件真的改回去了。
